# Demo Editorial Style

## Purpose
Keep demo collateral consistent, concise, and customer-safe across all presenter and packet documents.

## Core Language Standards
- Use timeline phrasing: 2-to-4 weeks.
- Use trust phrasing: Customer-visible reads and actions are authenticated and tenant-scoped; cross-tenant access is filtered or denied.
- Use rollout phrasing: demo-safe auth now, full production hardening next phase.

## Tone Standards
- Product-first and outcome-first.
- Avoid internal implementation jargon unless the audience is CTO/platform.
- Prefer direct sentence structures with action verbs.

## Script Structure Standards
- Keep agenda sections time-boxed.
- Keep closing ask explicit and measurable.
- Include one fallback path for sparse or failed data responses.

## Security Narrative Standards
- Keep one identity and one org throughout the demo.
- Never imply full enterprise auth completion unless explicitly validated.
- Avoid discussing debug or internal tool paths in live customer sessions.

## Formatting Standards
- Use sentence case for bullets.
- Keep bullets short and single-purpose.
- Use consistent heading capitalization and punctuation.

## Pilot Ask Standard Template
Approve a focused pilot on one org/site and one critical asset class for 2-to-4 weeks with agreed KPI baselines.
