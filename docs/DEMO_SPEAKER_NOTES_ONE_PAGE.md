# One-Page Speaker Notes

## Opening (20 seconds)
"We turn anomaly signals into actionable maintenance decisions with traceable follow-through, so teams move faster with more confidence."

## Flow (15 minutes)
1. Run detail value
- Show hypothesis, confidence, immediate actions, PM suggestions.
- Line to say: "This is decision clarity, not just alert visibility."

2. Execution proof
- Show PM proposal status, approval history, handoff state.
- Show repair-plan snapshot and parts.
- Line to say: "Recommendation to execution is visible and auditable."

3. Portfolio signal
- Show prioritized assets and outcomes summary.
- Line to say: "We can prioritize effort and measure if recommendations are accepted and completed."

4. Trust statement
- Line to say: "Customer-visible reads and actions are authenticated and tenant-scoped; cross-tenant access is filtered or denied."

5. Close and ask
- Line to say: "Next step is a focused pilot on one org/site and one critical asset class for 2-to-4 weeks with KPI baselines."

## Objection One-Liners
- "How is this different from dashboards?"
  - "Dashboards show what happened; this workflow guides what to do next and tracks execution."
- "Will this replace CMMS?"
  - "No, it improves decision and handoff quality into your CMMS process."
- "Can we trust recommendations?"
  - "Confidence, evidence context, and role-aware approval controls are built into the workflow."

## Live Guardrails
- Keep one identity and one org for full session.
- Do not switch tenant headers during demo.
- If data is thin, jump to known-good run and continue.
- Never debug implementation details live; offer follow-up.
